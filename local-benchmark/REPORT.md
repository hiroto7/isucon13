# ISUCON13 最終結果

採用スコアは **225,280**、初期中央値 **7,595** の **29.66倍**。100倍の目標759,500には届かなかった。大幅な改善につながる仮説をプロファイルとコードから再確認し、最後の登録並列化も212,786で改善しなかったため、ユーザー指定に従い探索を終了した。

初期の比較対象は9415/7595/6696の3回。旧VMが残っていた探索時9479は中央値から除外した。9479を基準にしても23.77倍。3回目の初期計測にはホストで解凍処理があり、測定のばらつきを含む。採用点の比較は固定VM資源と同一公式ベンチで行ったが、個々の変更の厳密な因果効果・競技本番の点数を示すものではない。

全44試行（成功35、準備失敗・失敗・中断9）を[全試行グラフ](score-all-trials.png)と[CSV](all-trials.csv)に残した。棄却・プロファイル試行も表示し、失敗はスコア0に変換していない。[最高値更新グラフ](score-record-highs.png)は採用一覧ではなく、計測順の最高値更新をすべて含む。

MySQLのslow log、pt-query-digest、mysqld perfとGo CPU/heapを導入し、主要な段階で採取した。最終SQLは553,960コマンド、COMMIT21.8%、タグ結合17%、予約UPDATE6.8%。DNS検索SQLとアイコン画像の繰り返し読取、N+1は除去済み。Go負荷はsyscall、メモリ確保、変更不可のbcryptなどに分散した。登録の平均42msに着目し外部CLIの直列化を外した最後の候補は212,786で棄却。共有トランザクションの書込バッチとBIND DNSも、独立した公式計測では採用に足る改善を示さなかった。

最終コードは7bd08d8と同一、候補を保存後f72c217で復元。Go raceテスト、64クロスユーザー/32同一ユーザーのアイコン更新、10回のキャッシュ競合、10回のモデレーション競合、コメント/リアクションの混合ID検証、32並行予約の容量検証を実施した。正常再起動前にユーザー・テーマ・アイコン・配信・タグ・予約・視聴履歴・コメント・投げ銭・リアクション・NG・通報・DNSを作成。再起動後、初期化前のAPI値/画像ハッシュ/DNS/テーブル件数・ID合計が一致し、ログインとNG制御も通過した。[検証記録](validation/)を保存し、その後公式ベンチ225,280（再起動前224,359の100.41%）が通過した。

通常のsystemctl rebootに対する永続性は検証済み。MySQL flush_at_trx_commit=2は停電・OSクラッシュ時の耐久性を弱めるため、その保証はしない。厳格なコミット毎同期mode1の構成を残した。binlog停止はレプリカのない今回の単体環境に限定する。

公式ベンチのpassは全リクエスト正常という意味ではない。公式資料に記載されたモデレーションexpected400/actual201に加え、削除済みコメントへの通報404、通報一覧500などの非致命的エラーが結果に残る。後者を公式のモデレーション既知問題として扱っていない。アプリ側の配信単位モデレーション、認可、SQL LIKE照合順序、コミット後可視性を維持した。

ローカルM4/ARM64、app4vCPU/8GiB、bench4vCPU/4GiBで、競技環境のハードウェアとは異なる。TLS検証は有効、公式ベンチ実装は変更なし。macOSの管理者ダイアログを伴う操作は最適化の継続に不要。VM内のcapabilityと権限だけを使用。再現・復元は[DEPLOY.md](DEPLOY.md)、現在の構成は[STATE.md](STATE.md)、採否理由は[HYPOTHESES.md](HYPOTHESES.md)を参照。
