# ISUCON13 最終結果

採用スコアは再起動後 **247,702**、最高値 **248,839**。初期中央値 **7,595** の **32.61倍**で、従来225,280から約10%改善した。100倍の目標759,500には届かなかった。公式解説を受けた追加監査で、配信情報・タグの繰り返し読取とタグ検索N+1が残っていると判明。これらを削減した候補は再起動後も改善を維持したため採用した。ただし爆発的な伸びではなく、微調整を追わず今回の2試行で追加探索を終了した。

初期の比較対象は9415/7595/6696の3回。旧VMが残っていた探索時9479は中央値から除外した。9479を基準にしても26.13倍。3回目の初期計測にはホストで解凍処理があり、測定のばらつきを含む。採用点の比較は固定VM資源と同一公式ベンチで行ったが、個々の変更の厳密な因果効果・競技本番の点数を示すものではない。

全46試行（成功37、準備失敗・失敗・中断9）を[全試行グラフ](score-all-trials.png)と[CSV](all-trials.csv)に残した。棄却・プロファイル試行も表示し、失敗はスコア0に変換していない。[最高値更新グラフ](score-record-highs.png)は採用一覧ではなく、計測順の最高値更新をすべて含む。

MySQLのslow log、pt-query-digest、mysqld perfとGo CPU/heapを導入し、主要な段階で採取した。旧到達点のプロファイルでは553,960コマンド、COMMIT21.8%、タグ結合17%、予約UPDATE6.8%。DNS検索SQLとアイコン画像の繰り返し読取は除去済みだったが、追加監査でタグ検索のN+1が残っていると判明した。Go負荷はsyscall、メモリ確保、変更不可のbcryptなどに分散した。登録の平均42msに着目し外部CLIの直列化を外した候補は212,786で棄却。共有トランザクションの書込バッチとBIND DNSも、独立した公式計測では採用に足る改善を示さなかった。

旧到達点225280は7bd08d8をf72c217で復元した構成。今回の最終コードは9140dbf。Go raceテスト、64クロスユーザー/32同一ユーザーのアイコン更新、10回のキャッシュ競合、10回のモデレーション競合、コメント/リアクションの混合ID検証、32並行予約の容量検証を実施した。正常再起動前にユーザー・テーマ・アイコン・配信・タグ・予約・視聴履歴・コメント・投げ銭・リアクション・NG・通報・DNSを作成。再起動後、初期化前のAPI値/画像ハッシュ/DNS/テーブル件数・ID合計が一致し、ログインとNG制御も通過した。[検証記録](validation/)を保存し、旧到達点では公式225,280が通過。今回も同じ永続性検証を行い、公式247,702（再起動前248,839の99.54%）が通過した。

通常のsystemctl rebootに対する永続性は検証済み。MySQL flush_at_trx_commit=2は停電・OSクラッシュ時の耐久性を弱めるため、その保証はしない。厳格なコミット毎同期mode1の構成を残した。binlog停止はレプリカのない今回の単体環境に限定する。

公式ベンチのpassは全リクエスト正常という意味ではない。公式資料に記載されたモデレーションexpected400/actual201に加え、削除済みコメントへの通報404、通報一覧500などの非致命的エラーが結果に残る。後者を公式のモデレーション既知問題として扱っていない。アプリ側の配信単位モデレーション、認可、SQL LIKE照合順序、コミット後可視性を維持した。

ローカルM4/ARM64、app4vCPU/8GiB、bench4vCPU/4GiBで、競技環境のハードウェアとは異なる。TLS検証は有効、公式ベンチ実装は変更なし。macOSの管理者ダイアログを伴う操作は最適化の継続に不要。VM内のcapabilityと権限だけを使用。再現・復元は[DEPLOY.md](DEPLOY.md)、現在の構成は[STATE.md](STATE.md)、採否理由は[HYPOTHESES.md](HYPOTHESES.md)を参照。

追加候補のSQL計測ではタグ取得60,770→1,497回、配信単件取得55,435→11,377回、全コマンド492,289→407,265に減った。失敗した予約をキャッシュ公開しないこと、初期化前の要求が新世代に古いIDを戻さないこと、タグsliceの共有による変更漏れをGo raceテストで検証。VMでは配信キャッシュを温めた後のアイコン更新が配信/コメント/リアクションのownerに反映すること、重複タグとタグ検索の重複結果・降順を確認。再起動前248,839→再起動後247,702（99.54%維持）。初期化前の保存データ一致も再検証し、validation/stream-cache-*に証拠を保存した。SQL削減率がスコア伸長率と一致するとは限らない。追加のTTL/ワイルドカード試験は実施していない。
